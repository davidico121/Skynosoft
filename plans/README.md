# Animation improvement plans

Generated by an `improve-animations` audit of the Skynosoft marketing site at commit `ec28ab5`. Each plan is self-contained — see the plan file itself for the full problem/target/steps; this is just the index.

| # | Title | Severity | Category | Status |
| --- | --- | --- | --- | --- |
| [001](001-mobile-menu-blur-budget.md) | Bring the mobile-menu backdrop blur under the performance budget | HIGH | Performance | DONE |
| [002](002-button-transition-all.md) | Replace `transition-all` with explicit properties on the shared button tokens | MEDIUM | Performance | DONE |
| [003](003-consolidate-easing-token.md) | Consolidate the duplicated easing token and fix the drifted duration outlier | MEDIUM | Cohesion & tokens | DONE |

## Recommended execution order

**001 → 002 → 003**, but all three are independent and touch non-overlapping lines, so they can be done in any order or in parallel by different executors without conflict.

- **001** is the highest-leverage fix (every mobile visitor hits this element) and the smallest (2 files, 1 line each) — do it first.
- **002** touches only `page-kit.tsx`, cascading to every page via the shared `BUTTON`/`BUTTON_SECONDARY` exports — no risk of merge conflicts with 001 or 003.
- **003** is the largest in file count (7 files) but each change is mechanical (swap a local `const` for an import). It incidentally touches `src/app/strategy/[slug]/page.tsx`, which is also where 002's sibling `transition-all` instances live uncorrected (by design — 002 only covers the shared `page-kit.tsx` tokens) — this is not a conflict, just worth knowing if a future plan tackles the remaining 20 `transition-all` sites.

## Dependencies between plans

None. No plan's target code depends on another plan having run first. The only shared file across plans is `src/app/strategy/[slug]/page.tsx`, touched by 003 only (001 and 002 don't touch it), so there is no ordering constraint there either.

## Known follow-on work (not planned yet)

- 20 of the repo's 22 `transition-all` occurrences are still unaddressed after plan 002 (which only fixes the two shared button tokens in `page-kit.tsx`). A future plan could work through the rest file-by-file, naming the exact properties that change at each site.
- `IslandNav.tsx`, `strategy/[slug]/page.tsx`, and `strategy/not-found.tsx` still locally re-declare `FOCUS` (and `IslandNav.tsx`/`[slug]/page.tsx` also re-declare `BUTTON`) instead of importing from `page-kit.tsx` — the same consolidation pattern as plan 003, just for a different token. Deliberately left out of 003's scope to keep that plan to one token.
